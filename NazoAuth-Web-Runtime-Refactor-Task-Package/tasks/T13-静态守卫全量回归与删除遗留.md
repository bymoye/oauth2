## 1. 任务目标

把单向职责边界变成可持续机器检查，确认旧接口和错误依赖已真正消失，并通过 Host Replacement Gate 证明替换 Framework / Runtime / Host 不需要修改 Application。

## 2. 前置条件

T00–P12所有局部验收完成；无悬而未决的安全/行为差异。

## 3. 精确修改范围

修改scripts/verify_static_contracts.py、check_persistence_dependency_graph.py；新增tests/unit/test_application_dependency_boundaries.py；更新受路径影响的既有Python source-policy测试、.github/workflows/code-quality.yml/conformance-security.yml中的必要package路径/命令；新增App tests/application_boundaries.rs 与 tests/host_replacement_contract.rs；最终清理各lib/mod/Cargo/lock及基线说明。

## 4. Symbol 级修改方案

I章节角色图、别名/optional/target解析、源码泄漏、canonical定义检查固定。旧server::bootstrap/cli/config/operator_task/recovery导出删；旧App domain concrete resolver/jobs删；SendCibaResponse/OAuthJsonErrorFields/RequestContext删。不要把同owner合理alias误判为compatibility。所有cfg(test)module显式装载；App smoke仅fake语义Ports+futures_executor。`host_replacement_contract.rs` 必须作为外部消费者 crate 编译，只使用 App public API + 内层 semantic crates；禁止引用 Native/Actix/Tokio，并至少覆盖 HTTP 型调用边界、security facts、one-shot batch 三类能力。

## 5. 数据流变化

最终：Host选择/启动/停止 → Adapters消费或实现内层能力 → App一次用例/单批 → Domain/Core规则。新增Web/Host只接外层，不改协议核心。

## 6. 必须保持的行为不变量

整个协议矩阵、tenant隔离、持久化schema/Valkey脚本、签名/DPoP/mTLS、HTTP字节/headers、runtime并发/取消、审计以及原依赖版本保持。性能退化不能通过调配置掩盖。

## 7. 禁止实现方式

不得为绿CI删除原source policy；不得全局allow/clippy禁用；不得skip failing tests；不得App测试依赖Native；不得把未运行OIDF标passed；不得增加未来空features/新crate。

## 8. 严格实施步骤

Step 1：角色图和负例测试加入既有脚本。Step 2：canonical/源码守卫和所有路径特定规则迁移。Step 3：运行App无Runtime smoke、Host Replacement Gate 与各测试--list核对装载；Host Replacement test 若因 public surface 不足失败，只能修正真实 Application public API，不能加入 Host backdoor。Step 4：执行L全部检查和原服务CI矩阵。Step 5：同部署回归外部conformance和性能；保存证据，逐项勾K；环境不可用项明确pending，不宣称全验收。
